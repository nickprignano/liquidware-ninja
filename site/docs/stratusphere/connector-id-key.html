Connector ID Key

verifiedReviewed 2026-10-29Source: stratusphere/connector-id-key.md

The Connector ID Key is Stratusphere's agent on each desktop. It calls back to the Hub (or a Collector) with what it measures. This repo rolls it out with Deploy-CidKey.ps1; this page holds the facts. Everything here cites Liquidware's support center or documentation; none of it has been through a lab run on real machines yet. Paths and the settings key changed in 6.7, so check the version.

Installer

  • Download it from your own Hub (Hub Administration > Connector ID Keys). It's never stored in this repo.
  • Silent install: <installer>.exe /s HUBADDRESS=<hub-fqdn-or-ip>. Other properties: MACHINEGROUP=, USERGROUP=, INSTALLDIR=, and logging with /l="C:\full\path.txt".
  • Silent uninstall: <installer>.exe /x /s, or /s REMOVE=TRUE (Liquidware notes it sometimes needs running twice).
  • The MSI is for Group Policy only: used outside Group Policy it doesn't uninstall cleanly. Scripted installs use the EXE.
  • Liquidware doesn't publish the installer's exit codes. Don't trust exit code 0 alone: check that the services exist and are running afterwards (an asked-for gap, upstream.md).

Sources: command line options, Intune deployment.

On the machine

  • Services: tntgrd, tntdatasvc and tntupdsvc (antivirus exclusions article).
  • Settings key: HKLM\SOFTWARE\Liquidware Labs\Connector ID from 6.7. Up to 6.6.2-2 on 64-bit Windows it was HKLM\SOFTWARE\Wow6432Node\Liquidware Labs\ConnectorID (no space). It holds hubAddress, GROUP and USERGROUP for Group Policy installs.
  • Program folder: C:\Program Files\Liquidware\Connector ID from 6.7; before 6.7, C:\Program Files (x86)\Liquidware Labs\Connector ID.
  • idcontrol.exe in the program folder controls the key from a script: start, stop, status, properties, callback (force a report), debug on|off, version.
  • A ca\cert.txt file in the program folder means the key received its first instructions from the Hub (support article).

Callbacks

The key calls the Hub on TCP 443. An NSG or firewall between the desktops and the Hub must allow it (azure/networking.md).

  • The address it calls is the first line of ca\public\mgrcert.pem in the program folder. It comes from the Hub's DNS name (Configuration > Edit Network Configuration) when the installer was downloaded, so set the Hub's DNS name before downloading the installer. A key with the wrong address needs reinstalling from a fresh download, or mgrcert.pem edited and its service restarted (support article).
  • Desktops that can't reach the Hub can register with a CID Collector instead (Stratusphere 6.5.1 or later can use the Collector's name as the callback address) (support article). The mgrcert.pem can't be downloaded from a Collector; copy it from a working machine.

Desktops created later

Azure Run Command reaches only the machines that exist when it runs. Session hosts created later from an image need the key in the golden image, or an Intune or Group Policy assignment. The image side belongs to the AVD knowledge base (family.yaml).
