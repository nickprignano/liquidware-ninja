Before you build something

Every change follows the guardrails. Run the prior-art check first (python3 scripts/kb/prior_art.py "<topic>", see curation.md).

How to add to it

  • Without editing files: open a Knowledge base feedback, Known error or Suggest an expert to follow issue. When a maintainer labels it kb-accepted, a workflow turns it into a pull request.
  • With a pull request: add a bullet to the matching topic page, say what happened, the fix and the versions it applies to, and mark anything you haven't confirmed with the *unverified* marker. Known errors go in troubleshooting/known-errors.yaml. Decisions are a copy of decisions/template.md at the next number, proposed until the maintainer says yes. Run python3 scripts/kb/build.py and python3 scripts/kb/validate.py before pushing.

Format

Page front matter (title, summary, topic, status, last_reviewed) is checked against schema/page.schema.json. Decisions are MADR 4 records. The YAML data files each have a JSON Schema in schema/, and the Markdown tables and llms.txt are generated from them. The full system is in the 2ndbrain spec.
