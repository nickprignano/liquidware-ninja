Known errors

verifiedReviewed 2026-10-29Source: troubleshooting/README.md

Errors we've hit, what caused them and what fixed them. The table is generated from known-errors.yaml; fixes marked *(unverified)* haven't been confirmed yet.

Symptom Cause Fix Source
Connector ID Keys are installed but the Hub shows no data from them The key calls the address in its mgrcert.pem, taken from the Hub's DNS name when the installer was downloaded; the address is wrong or unreachable on TCP 443 Set the Hub's DNS name (Configuration > Edit Network Configuration), download the installer again and reinstall, or edit mgrcert.pem and restart the key's service; allow TCP 443 from the desktops to the Hub link
On a multi-session AVD host using FlexApp through app attach or RemoteApp, the first user's app launches but the next user's never does The Click-To-Layer engine's extra validation fails falsely for the second session As an administrator, set Validate to False in C:\Program Files\ProfileUnity\FlexApp\CTL\JitCut.dll.config, then restart the host to clear stuck sessions link
"License Not Authorized" from the Stratusphere API after the license was updated The API module caches the previous license Restart the Hub appliance link
kb-freshness lists every tracked expert as "nothing in the digests since ; check the feed still works" on a new KB Expert yield was computed from digest issues before any existed, or before a newly scored expert had a month of digests freshness.py counts only digests since the expert was scored and skips the check until MIN_DIGESTS (4) exist curation.md
kb-freshness counts unverified claims on a page whose only match is prose about the marker, and misses claims marked (unverified) The inline-marker regex matched the word inside instructions and bold **Unverified labels, and didn't allow a parenthesis after the asterisk The regex now matches (unverified) and skips bold labels; write prose that names the marker in backticks so it's ignored curation.md
Unticked kb-digest issues pile up week after week, and the kb-freshness issue stays open after every item is fixed The curator only opened digests and the freshness job only ran its issue step when items != 0; nothing closed an issue once it was stale or clean A new digest closes older open digests with nothing ticked, linking the new one; the freshness job closes its issue when the check finds 0 items curation.md
A curator source fails with "HTTPError: HTTP Error 500: Internal Server Error" (seen in the family on YouTube channel feeds) The feed host returns transient 5xx responses sources.http_get retries a 5xx once after 5 seconds; a source that still fails is listed at the bottom of the digest curation.md
Unattended FlexApp capture queued from a server's C:\Windows\Installer*.msi cached package fails mid-install asking for source media or missing cabinet files Windows Installer strips embedded MSCF cabinet streams from many cached MSIs in C:\Windows\Installer to save disk space, leaving only table metadata Verify the cached MSI contains an embedded MSCF cabinet header before capture; if stripped, resolve the installer from the registry InstallSource UNC path, recipe catalog, or original vendor media packaging-and-delivery.md
A captured FlexApp package mounts cleanly, but launching the application executable exits immediately with code 0xC0000135 (-1073741515 / STATUS_DLL_NOT_FOUND) or 0xC000007B (STATUS_INVALID_IMAGE_FORMAT) The application depends on a shared runtime (such as VC++ Redistributable or .NET Desktop Runtime) absent from the session host base image, or a 32-bit/64-bit prerequisite runtime was not captured in the composite layer Install shared runtimes (VC++, .NET, WebView2) in the session host golden image and bundle app-specific prerequisites (pinned JRE, Crystal Reports, ODBC drivers) as pre-install steps in a composite FlexApp capture packaging-and-delivery.md
